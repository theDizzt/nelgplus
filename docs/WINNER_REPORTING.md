# Discord Winner Reporting

## Flow

The Level 35 Winner screen collects a nickname, a hidden password, and an optional completion message. The arrival-time field is displayed as readonly UTC for the player, but the browser does not submit that value. `api/winner-report.js` generates the authoritative UTC value when the request reaches the server, then relays the report to a private Discord channel.

The report is only a review request. It never writes to `hall-of-fame.json` automatically. After reviewing the Discord message, the administrator adds an approved entry to the static JSON file manually.

## Required Vercel Environment Variables

```env
DISCORD_WINNER_WEBHOOK_URL=https://discord.com/api/webhooks/WEBHOOK_ID/WEBHOOK_TOKEN
ALLOWED_ORIGIN=https://example.github.io
```

`DISCORD_WINNER_WEBHOOK_URL` is a server secret and must be configured only in the Vercel dashboard. Never use a `VITE_` prefix for the webhook URL and never commit it to the repository.

If the game remains on GitHub Pages while the function runs on Vercel, set the public frontend build variable to the complete function URL:

```env
VITE_WINNER_REPORT_API_URL=https://example.vercel.app/api/winner-report
```

When the game and function share the same Vercel deployment, the frontend can use the default `/api/winner-report` path.

## Local Development

Run `run-game.bat`, or run the following command directly:

```sh
npm run dev:full
```

This uses `vercel dev` on port 5173, so the Vite game and `api/winner-report.js` are served from the same origin. The first run may prompt for Vercel login and project linking. Once the folder is linked, Vercel automatically loads the project's Development environment variables into memory. Configure these variables for the Development environment in Vercel:

```env
DISCORD_WINNER_WEBHOOK_URL=https://discord.com/api/webhooks/WEBHOOK_ID/WEBHOOK_TOKEN
ALLOWED_ORIGIN=http://127.0.0.1:5173,http://localhost:5173
```

Do not commit `.env`, `.env.local`, or `.vercel/`.

## GitHub Pages and Vercel Deployment

This repository deliberately uses two deployments:

- GitHub Pages hosts the static game.
- Vercel hosts the same repository and provides `/api/winner-report`.

In Vercel, import the GitHub repository and add `DISCORD_WINNER_WEBHOOK_URL` and `ALLOWED_ORIGIN` under **Project Settings > Environment Variables**. For this repository's default GitHub Pages address, use `https://thedizzt.github.io` as the allowed origin. An HTTP Origin never includes the `/nelgplus/` path.

In GitHub, open **Settings > Secrets and variables > Actions > Variables** and add this repository variable:

```text
Name:  VITE_WINNER_REPORT_API_URL
Value: https://YOUR_VERCEL_PROJECT.vercel.app/api/winner-report
```

The Pages workflow passes this non-secret public URL into the Vite build. Never add the Discord webhook as a GitHub Actions variable or as a `VITE_` variable.

## Validation

- Nickname: required, 1-32 characters after trimming
- Hidden password: required, 1-64 characters and displayed as a password field
- Message: optional, up to 240 characters after trimming
- Arrival time: generated only by the Vercel Function
- Discord mentions: disabled through `allowed_mentions`
- CORS: same-origin requests or an origin listed in `ALLOWED_ORIGIN`

The hidden password is wrapped in Discord spoiler markup so reviewers must deliberately reveal it. The API does not store any report in a database or local file.

## Security Limitations

A browser-only game cannot prove that a player completed the level legitimately. The endpoint also needs persistent rate limiting or a challenge system before a large public release. Treat all Discord submissions as untrusted review candidates and never copy a record into the Hall of Fame without manual verification.

## Verification

1. Submit a valid report and confirm that Discord receives all four fields.
2. Confirm that the displayed client time is readonly and the Discord time is generated by the server.
3. Confirm that the hidden password is masked in the browser and spoiler-hidden in Discord.
4. Reject payloads exceeding any field limit.
5. Reject requests from origins outside `ALLOWED_ORIGIN`.
6. Confirm that the webhook URL never appears in the built frontend JavaScript.
